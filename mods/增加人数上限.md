# 增加人数上限（Invokyr Player Limit）

把游戏默认的 **6 人**人数上限提高到你设定的值，让更多玩家能加入同一房间 / 大厅。

- **GUID**：`top.juluo.invokyr.playerlimit`
- **装机**：`InvokyrPlayerLimit.dll` 放到 `BepInEx/plugins/增加人数上限/`
- **只改房主端即可**（房主开房时生效，全员受益）

## 使用

默认上限调整为 **8**，进游戏即可生效；也可以在 `BepInEx/config/top.juluo.invokyr.playerlimit.cfg`（或用「配置修改」mod 面板）里改：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `General > Enable` | `true` | 总开关，关闭后本 mod 不干预人数上限 |
| `General > PlayerLimit` | `8` | 期望的最大玩家数，需 ≥ 6（游戏原生上限） |
| `General > ExtraPortraits` | `true` | 是否把大厅玩家头像格补齐到人数上限（克隆头像格，切换建模正常） |
| `Replicate > EnableReplicate` | `false` | **实验性，建议保持关闭**。是否复刻内置角色以扩充可用角色数 |

> **实际生效值 = min(PlayerLimit, 可用角色数)**。因为每个玩家必须占用一个不可重复的任务建模（买属性加成是绑在建模上的），所以哪怕把 PlayerLimit 设得很大，实际能加入的人数也不会超过游戏可用建模的数量。游戏内置可用角色为 **8**（本 mod 会自动读取并夹取），因此当前实际上限为 8。

> **关于 `EnableReplicate`（突破 8 人）**：把它设为 `true` 会让本 mod 尝试向角色列表注入"复刻角色"以支撑更多玩家。但已验证：游戏 native 端不识别注入的复刻角色（角色分配仍只认 8 个内置角色），并可能导致返回主菜单时崩溃。**因此建议保持默认 `false`**；要突破 8 人仍需游戏自身提供更多角色。

改完**保存并生效**（或重启游戏）即生效。

## 工作原理

通过两个入口把人数上限提到设定值：

1. **`VhsNetworkManager.MaxPlayers`**：游戏读取玩家上限的属性，patch 它的 getter，任何地方读到上限都返回设定值（用于人数校验和界面显示）。
2. **`SteamLobby.Create`**：房主建 Steam 大厅时传入的 `maxMembers` 参数，patch 后强制改为设定值，让 Steam 大厅能容纳更多人。

两个入口都做了「取较大值」处理，只往高提、不会把上限压回去。这些改动都在房主 / 服务端一侧，客户端无需装本 mod。

此外，大厅墙上一排玩家头像格（用于切换建模 / 查看属性 / 死亡骷髅）默认只有 6 个，上限提到 8 后第 7、8 个玩家会没有格子。本 mod 在服务端把头像格克隆补齐到人数上限，并给克隆头像格注册独立网络身份（`NetworkIdentity` + `Spawn`），使它们在切换建模时也能正常读写网络状态、不产生空引用报错。
